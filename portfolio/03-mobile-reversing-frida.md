# Mobile Security & Reversing

## 개요

모바일 애플리케이션 진단에서 수행해 온 **역공학, 보안 로직 분석, Root Detection 우회 가능성 검증, Frida 기반 런타임·메모리 분석** 경험을 정리합니다.

실제 고객사 APK나 내부 코드는 공개하지 않으며, 향후 공개 가능한 테스트 APK에서 동일한 분석 과정을 재현할 예정입니다.

---

## 진단 흐름

### 1. 정적 분석

- APK 구조 확인
- Manifest 및 주요 Component 확인
- 보안 관련 클래스와 메서드 탐색
- Root Detection 등 단말 보안 로직 위치 확인
- 중요정보 하드코딩 여부 확인
- API Endpoint 및 통신 관련 코드 확인

### 2. 실행 흐름 확인

앱의 주요 기능을 직접 실행하면서 다음을 연결해 봅니다.

- 화면 기능
- 내부 메서드
- API 요청
- 서버 응답
- 클라이언트 측 검증

### 3. Root Detection 분석

Root Detection이 적용된 경우 단순히 탐지 여부만 확인하지 않고 다음을 봅니다.

- 어떤 조건을 확인하는지
- 어느 메서드에서 판단하는지
- 탐지 결과가 앱 기능에 어떻게 연결되는지
- 단일 검사인지 여러 검사가 조합되는지

### 4. Frida 기반 동적 분석

Frida를 이용해 런타임에서 다음을 확인합니다.

- 특정 메서드 호출
- 인자 및 반환값
- 보안 로직 실행 여부
- 메모리 및 런타임 데이터
- 클라이언트 검증 결과 변경 시 기능 영향

목적은 단순 우회 자체가 아니라 **보안 로직이 어디에서 수행되고 실제 보안 경계가 클라이언트에만 존재하는지 확인하는 것**입니다.

### 5. API 연계 검증

보안 로직 우회 이후에도 서버가 독립적으로 권한과 입력값을 검증하는지 확인합니다.

---

## 판단 기준

- 클라이언트 보안 기능이 우회되더라도 서버 측 보안이 유지되는가
- 중요정보가 런타임 또는 로컬 영역에 불필요하게 존재하는가
- 클라이언트 검증 결과가 서버 동작에 직접 영향을 주는가
- API가 앱의 검증 결과를 신뢰하는가

---

## 개선 방향

- 클라이언트 보안 기능을 보조 통제로 사용
- 핵심 권한·업무 검증은 서버에서 수행
- 중요정보의 불필요한 로컬 저장 최소화
- 보안 로직 단일 의존 방지
- 우회 이후 노출되는 API 공격면 별도 검증

---

## 공개 증적 구성

공개 가능한 테스트 APK를 준비한 뒤 다음 정도의 증적만 추가합니다.

1. 정적 분석 화면
2. Root Detection 관련 코드 위치
3. Frida로 메서드 호출 확인
4. 런타임 값 확인
5. 우회 전/후 동작 차이
6. 서버 측 검증 여부
7. 개선안

핵심은 도구 사용 화면보다 **분석 과정과 판단 근거**를 보여주는 것입니다.
