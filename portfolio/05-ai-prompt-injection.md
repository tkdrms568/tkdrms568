# AI Chatbot Security Assessment

## 개요

메가스터디와 롯데이노베이트 프로젝트에서 수행한 AI 챗봇 보안 진단 경험을 기반으로, LLM 기반 서비스에서 Prompt Injection과 내부정보 노출 가능성을 검증하는 관점을 정리합니다.

실제 고객사의 프롬프트, 내부정보, 운영정책은 공개하지 않습니다.

---

## 1. 진단 목표

단순히 모델이 금지된 문장을 출력하는지 보는 것이 아니라 다음을 확인합니다.

- 시스템 지시 우회 가능성
- 내부 프롬프트 및 정책 노출 가능성
- 민감정보 또는 내부정보 노출 가능성
- 역할 전환·반복 질의 등에 대한 통제
- 사용자 입력과 내부 컨텍스트의 분리
- 서비스 기능과 연결된 경우 권한 범위

---

## 2. 공격 시나리오 구성

### Direct Prompt Injection
사용자가 직접 입력한 지시가 기존 정책보다 우선 처리되는지 확인합니다.

### Role-play / Context Shift
역할극이나 문맥 전환을 통해 기존 제한이 약화되는지 확인합니다.

### Repeated Query
동일 목적의 질문을 다양한 형태로 반복했을 때 정보가 누적 노출되는지 확인합니다.

### Instruction Disclosure
내부 지시, 정책 또는 컨텍스트 내용을 직접·간접적으로 노출할 수 있는지 확인합니다.

### Data Extraction
서비스에 연결된 정보가 사용자의 권한 범위를 넘어 노출되는지 확인합니다.

---

## 3. 영향도 판단

Prompt Injection이 성공했다는 사실만으로 위험도를 판단하지 않습니다.

- 실제 내부정보가 노출되는가
- 개인정보나 민감정보에 연결되는가
- 다른 사용자의 데이터로 확장 가능한가
- 외부 기능 또는 Tool 호출과 연결되는가
- 반복 공격으로 영향이 누적되는가

를 함께 확인합니다.

---

## 4. 개선 방향

- 시스템 지시와 사용자 입력의 역할 분리
- 민감정보를 모델 Context에 불필요하게 포함하지 않도록 설계
- 모델 출력 전 후처리 및 정책 검증
- Tool / API 호출 전 별도 권한검증
- 사용자별 데이터 접근범위 제한
- 공격 패턴 로깅 및 모니터링
- 단일 프롬프트 차단에만 의존하지 않는 다중 방어

---

## 5. 재점검

개선 후 동일 문장 하나만 다시 시도하지 않고 다음을 변형해 확인합니다.

- 표현 변경
- 역할극
- 다단계 질의
- 반복 질의
- 다른 언어
- 간접 지시

---

## 공개 포트폴리오 구성

향후 테스트 챗봇에는 실제 내부정보 대신 다음과 같은 가짜 데이터를 사용합니다.

```text
INTERNAL_CODE=DEMO-SECURITY-2026
```

이를 통해 **공격 시나리오 → 노출 → 개선 → 재점검**을 안전하게 재현할 수 있습니다.
