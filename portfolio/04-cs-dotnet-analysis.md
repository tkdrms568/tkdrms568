# C/S · .NET Application Security Analysis

## 개요

대형 제조 환경의 C/S 프로그램 진단 경험을 바탕으로, **클라이언트 내부 로직과 서버 통신을 함께 분석하는 방식**을 정리합니다.

실무에서는 dnSpy와 EchoMirage를 사용해 .NET 애플리케이션 구조와 통신 흐름을 분석했습니다.

---

## 1. 프로그램 구조 파악

- 실행 파일 및 주요 DLL 확인
- .NET Assembly 구조 확인
- 인증·권한·통신 관련 Namespace와 Class 탐색
- 주요 업무 기능과 메서드 연결

---

## 2. dnSpy 분석

dnSpy를 이용해 다음 내용을 확인합니다.

- 클라이언트 측 인증·권한 로직
- 입력값 검증
- 서버 요청 생성 과정
- 중요정보 처리
- 클라이언트에 포함된 업무 로직
- 예외 처리 및 Debug 정보

목적은 "코드가 보인다"는 사실이 아니라 **어떤 보안 판단이 클라이언트에 의존하는지** 확인하는 것입니다.

---

## 3. 통신 흐름 분석

EchoMirage 등을 활용해 애플리케이션과 서버 사이의 통신을 확인합니다.

- 요청 시점
- 전달 파라미터
- 세션·인증정보
- 서버 응답
- 클라이언트에서 처리되는 상태값

---

## 4. 교차 분석

코드와 통신을 따로 보지 않고 연결해서 확인합니다.

예:

1. UI에서 기능 실행
2. dnSpy에서 관련 메서드 확인
3. 통신 데이터 확인
4. 클라이언트 검증 위치 확인
5. 서버 측 검증 여부 확인
6. 변조 시 실제 영향 확인

---

## 5. 주요 검토 포인트

- 클라이언트 권한검증 의존
- 상태값 변조
- 중요정보 하드코딩
- 입력값 검증 부족
- 서버 요청 파라미터 변조
- Debug·예외정보 노출
- 로컬 파일 또는 설정정보 보호

---

## 6. 개선 방향

- 핵심 권한·업무 검증 서버 측 수행
- 클라이언트 전달값 재검증
- 중요정보 클라이언트 내 최소화
- 통신구간 보호
- 예외·Debug 정보 외부 노출 제한
- 유사 기능 확산 점검

---

## 실무에서의 의미

C/S 진단에서는 웹 진단처럼 HTTP 요청만 보는 것으로 충분하지 않은 경우가 있습니다.

**프로그램 내부 로직 → 통신 → 서버 처리**를 연결해서 봐야 클라이언트 우회가 실제 보안 영향으로 이어지는지 판단할 수 있습니다.
