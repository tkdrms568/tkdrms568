# Web / API

웹 진단에서 가장 많이 보는 부분은 인증·인가와 입력값 처리입니다. 화면에서 기능이 막혀 있더라도 실제 요청을 바꿨을 때 서버에서 다시 검증하는지 확인하는 편입니다.

예를 들어 사용자별 권한이 있는 서비스라면 다음 순서로 봅니다.

- 일반 사용자와 관리자 요청 비교
- 객체 ID나 상태값 변경
- 다른 사용자 데이터 접근 여부 확인
- 화면 제어와 서버 권한검증이 분리되어 있는지 확인
- 조회뿐 아니라 수정·삭제·승인 같은 상태 변경 기능도 확인

단순히 다른 ID가 조회된다는 것보다, 어디까지 영향이 이어지는지 확인한 뒤 위험도를 판단합니다.

현재 공개용으로 만든 [Web/API Security Lab](../security-lab/web-api/)에는 다계정·다부서 비용 승인 시나리오를 넣어두었습니다. 여기서는 객체 소유권, 부서 범위, 상태 전이, 자기 승인 같은 업무 로직을 비교할 수 있습니다.

실무에서는 SQL Injection, XSS, CSRF 같은 기본 취약점도 함께 점검하지만, 경력이 쌓일수록 인증·인가와 업무 로직처럼 서비스 구조를 이해해야 찾을 수 있는 문제를 더 중요하게 보고 있습니다.
